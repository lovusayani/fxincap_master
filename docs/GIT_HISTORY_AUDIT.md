## 3. Root cause of the poor messages

Two mechanisms in the repository generate them:

1. [deploy-remote.ps1](../deploy-remote.ps1) — `$msg = "fc" + (Get-Date -Format "yyyyMMddHHmmss")`,
   then `git add . && git commit -m $msg && git push`. Every `fc2026…` commit came from this script.
2. [.gitmessage.txt](../.gitmessage.txt) — a Conventional Commits template. The four
   `<type>(<scope>): <short summary>` commits are the template committed unedited.

The template itself is good. The problem is a deploy script that commits everything under a
timestamp, which also makes each commit an undifferentiated bulk change.

## 4. 🚨 Security-relevant history

**The root commit added 382 user-uploaded files, including 210 KYC identity documents and 158 deposit
screenshots belonging to real customers.** Commit `52fc638` deleted them from the working tree, but
the blobs remain fully reachable in history.

This is documented in full, with remediation steps, in [SECURITY.md](./SECURITY.md) §7. It is the
one finding that makes a history rewrite a genuine necessity rather than a cosmetic preference.

**Credentials:** no `.env` file other than `.example` templates was ever added on any branch.
Despite its message, `1d95474` adds files only — the history appears to be a post-scrub import. No
credential rotation is needed on account of git history.

## 5. Large blobs

The ten largest blobs in the object database are all user uploads from the root commit — the largest
is a 4.3 MB profile photo, and seven KYC images exceed 1 MB. No build artefacts, archives or
`node_modules` were ever committed.

### ⚠ `origin/dev` must never be deployed from

`dev` did not diverge from `main` part-way through — it branched at the **root commit** and never
received real work:

```
$ git merge-base main origin/dev
1d95474                                            # the root commit

$ git log --oneline main..origin/dev
9ba7440 chore: final webhook completion check      # empty — 0 files changed
16baaa2 chore: webhook e2e final verification      # empty — 0 files changed
11d5962 chore: trigger dev deploy webhook test     # empty — 0 files changed

$ git diff --stat origin/dev..main | tail -1
483 files changed, 10079 insertions(+), 4271 deletions(-)
```

The three "ahead" commits are **empty webhook-test commits**. Everything real is on `main`, including
the entire deploy chain:

```
origin/dev:deploy-prod.sh              ABSENT
origin/dev:install-prod.sh             ABSENT
origin/dev:run-prod.sh                 ABSENT
origin/dev:deploy/webhook-server.cjs   ABSENT
```

Because `deploy-prod.sh` runs `git reset --hard origin/$DEPLOY_BRANCH`, a deploy from `dev` would
**delete the deployment scripts from the production server** and break deploys permanently.

`DEPLOY_BRANCH` defaults to `dev` throughout the codebase, so the live `.deploy.env` must be
overriding it to `main` — production has been deploying successfully, which is impossible from `dev`.
`TODO: verify on production server`: `grep DEPLOY_BRANCH .deploy.env`.

`dev-clean` and `live-server-updates` are fully merged into `main` and could be deleted. `dev` should
either be deleted or fast-forwarded to `main`. **Deleting branches was excluded from this task** — no
branches were touched.
